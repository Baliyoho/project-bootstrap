## 約束

| ID | 決定 |
|---|---|
| D1 | 同分支、同工作樹只有一個 writer。靠 origin 上的「工作中」標記協調，是訊號不是鎖 |
| D2 | 機器查得到就實查；查不到明示未驗證 |
| D3 | 共用制度只有一份權威內容 |
| D4 | 專案預設用最新制度；例外由使用者宣告 |
| D6 | 專案內容自由；共用制度只能加嚴或填空 |
| D7 | 新專案取得一個安裝程式（單一檔 `bootstrap.py`），由程式寫檔；制度與專案內容的邊界由 `owners.json` 呈現 |
| D8 | 規模與平台照[目標與範圍](goal-and-scope.md)：兩個工具、十個以內的專案、一次一個 session；平台分三期，不支援 Antigravity |
| **D9** | **執行屏障委託工具原生的權限與沙箱。本專案只負責資訊層。工具不提供就標「未達成」，不自製替代品** |
| **D10** | **規則有准入與退場。** 進入條件：觀察到重複發生的失敗，登記當時的模型、工具、日期。退場條件：換模型後重跑反例，不再重現就移除，理由留在理由檔 |
| **D11** | **常態入口有預算。** 每個 session 必載的共用制度 ≤ 40 行；專案的 `AGENTS.md` 全檔 ≤ 100 行；`HANDOFF.md` ≤ 80 行。超過的移到碰到才讀的參考檔 |
| **D12** | **入口寫事實與規則，不寫逐步程序、判讀表、專案概觀。** 逐步程序只能是碰到才讀的參考檔 |
| **D13** | **要擋的事只用機械手段**（hook、git 機制、CI），不寫成散文後當作有擋 |
| **D14** | **改制度要有對照。** 新增或保留一條有成本的規則前，用 handoff-ab 的方法比「有它」與「沒有它」；評分只查機器查得到的結果；每個 FAIL 人工看原始資料後才採用 |
| **D15** | **制度本身的成本有上限。** 單次決策的對照實測 ≤ 24 次模型呼叫、只用訂閱額度、逐批經使用者批准；任一用量窗到 85% 就停；不為制度維護常態並行多個 agent |

D9、D12、D13 一起讀：**資訊進入口，強制進 hook，執行屏障交給工具。** 三者不互相代替。

不承諾任何本專案自己做不到的阻擋。

## 非目標

- 不以永久的平台分支維護多份核心。〔計畫 §5〕
- 不恢復凍結的執行屏障與簽章發布通道。〔計畫 §5〕
- 不以自動信任 hook、繞過沙箱或搬運憑證換取速度。〔計畫 §5〕
- 不一次重寫所有程式、不先導入框架、不預先宣稱跨作業系統或 Python 下限通過。〔計畫 §5〕

## 本 repo 的例外

本 repo 對 F46 的正式例外（D4 的使用者宣告、F34 的看得見）：

> 宣告不等於 F46 已達成，實作狀態看[現況索引](../docs/status.json)。要撤銷這條宣告（改成補裝），是改使用者的決定，不是改措辭。理由在[理由檔](../docs/rationale.md#what)。
