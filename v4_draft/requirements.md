# 需求

> 最後更新：2026-11-22
> v4 草稿，從需求決策書 v3 第 4 節拆出。回答「這個產品要做到哪些事、做到多強」。每條為什麼是這個強度在[理由](rationale.md)，由哪個部件承擔在[部署目標形狀](target-shape.md)，怎麼驗在[驗收](acceptance.md)。

## 怎麼讀

- **編號**：沿用穩定 ID，不重編；已退役的 ID 不列在這裡，見[歷史候選](history.md)。
- **強度**：留痕／提示／偵測／阻擋四級。**待補**：v3 寫「定義同 v2」，定義只在 v2 封存原件裡，v4 要自己寫出來。
- **類別**：**必要**＝交付義務；**委託**＝依 D9 交給工具，本專案不實作；**想要**＝不構成交付義務。
- **說明**：只寫需求本身的範圍限定，不寫怎麼做。
