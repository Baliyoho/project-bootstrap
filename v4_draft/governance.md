# 文件權威與變更

> 最後更新：2026-11-22
> v4 草稿，從需求決策書 v3 的檔頭、第 7 節與第 8 節開頭拆出。回答「這套需求文件誰說了算、怎麼改、歷史放哪」。下面的「本檔」指 v3 決策書；拆成多份之後怎麼稱呼，v4 要重新決定。

## 唯一需求書

本檔是現行需求權威，也是唯一需求書。v2 決策書凍結封存在 `archive/docs/requirements-decision-v2.md`，逐位元組不改，不被任何程式讀取；它的條文、Q1–Q31 與逐條否決理由只供經使用者同意的歷史回溯。

## 現況與歷史

本檔只寫現在要什麼：目標、約束、強度、驗收與待決事項。修改直接改寫成現況，條文只附 Q 編號或日期當出處；同一個 commit 在[歷史紀錄](../docs/history/project-bootstrap-requirements-v3-history.md)的「修改紀錄」加一筆（日期、改了哪裡、牽涉的 ID 或 Q、出處），被改掉的原文值得留就放它的「從條文移出的經過」。歷史紀錄到下一版時跟本檔一起封存。

## 歷史的冷熱兩區

`docs/history/` 是熱歷史：跟現行版本有關、還會增加的紀錄（目前是本檔與實施計畫的歷史紀錄），碰到才讀，讀它不用先經使用者同意，程式可以讀，連結照常檢查。根目錄 `archive/` 是冷區：結案或被取代、不再更動的東西，平常不讀，要回溯先經使用者同意。`archive/docs/` 放文件，程式不讀；`archive/v2-*/` 放退休的 v2 程式與說明，不執行，程式與現況索引都不引用。熱歷史到下一版時連同對應的文件搬進 `archive/docs/`。

## 版本更替

現行版本是本檔的「決策版本」，也就是 `AGENTS.md` 的規則連到的那份決策書。新的穩定版本成為權威（AGENTS 改連新版決策書）之後，現行檔案裡屬於舊版本名稱的一切，包括檔名或資料夾名帶舊版本號的文件與程式、程式裡帶舊版本號的識別字與標籤，都要刪除、封存到 `archive/`，或改成新版本的名稱；現行程式也不得引用 `archive/` 底下以版本號開頭的封存資料夾。文件內文拿舊版本作對照或交代歷史不算；版本號比現行新的草稿不受影響。`verify_bootstrap.py`「版本更替」守。

## 約束範圍與修改

本檔與實施計畫約束本 repo 的所有工作。本檔全文都約束；計畫只約束分期、範圍、暫緩與取捨，不約束每一步的做法。要偏離就先改文件，改文件要有使用者在聊天中的決定，並照「現況與歷史」在歷史紀錄記一筆；AI 可以提案，不能自己改。兩份都沒寫到的事不算偏離；會新增或改變需求的，先問使用者。

## 進度不寫在這裡

逐 ID 的實作狀態在[現況索引](../docs/status.json)，本檔不寫進度。定稿不等於實作完成。

## 跟實施計畫的分工

從現況走到本檔需求的路線、分期與暫緩項目在[實施計畫 v3](../project-bootstrap-implementation-plan-v3.md)；它只引用本檔的 ID，不重述需求。

## 待決事項怎麼登記

要使用者決定的事登記在[待決事項](open-questions.md)，格式照[歷史紀錄](../docs/history/project-bootstrap-requirements-v3-history.md)第 2 節：編號、登記日期、起因、選項、影響的 ID、狀態。決定之後，完整紀錄搬到歷史紀錄的「決策紀錄」，待決清單刪掉，條文改成現況並附 Q 編號。已決的 Q 被後來的 Q 撤銷或改掉一部分時，在舊的那筆標「被取代」或「部分被取代」並寫明是哪一個 Q。
