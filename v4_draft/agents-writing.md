# AGENTS 的寫作規範

> 最後更新：2026-11-23
> v4 草稿，從協作系統原則草稿第 4 節拆出；全檔出自原則草稿，不另標。回答「AGENTS 要怎麼寫」。為什麼另訂這份規範在[理由](rationale.md)的「設計原則的理由」，依據在[證據](evidence.md)的「原則草稿引用的依據」；一般文件的原則在[設計原則](design-principles.md)。

本 repo 的 `AGENTS.md` 與部署包的 AGENTS 範本都適用。

1. **放進來的門檻**：一句話要同時符合兩個條件。
   1. AI 自己看不出來：讀程式碼或其他文件找不到，或找得到但不會想到要去找。
   2. 不知道就會闖禍：大多數 session 都會碰到，或很少碰到但錯了救不回來。

   不符合的不放；偶爾會用到的，只寫一句「做 X 時讀 Y」。
2. **不放**：專案介紹（README、ARCHITECTURE 的家）、經過與版本來由（歷史紀錄的家）、理由（理由檔的家，只留連結）、步驟（維護手冊或 skill 的家，只留連結）、祕密。
3. **能用程式擋的交給程式擋**：驗證器或 hook 擋得住的錯，AGENTS 只留一句規則讓 AI 知道有這條，細節不寫。這一句仍要留。
4. **寫法**：一條只講一件事，用具體的指令與路徑，不寫模糊的話；規則只放在規則清單裡（共用、專用各一份），不散在別的節；用平常語氣，不堆粗體與「絕對」，最重要的幾條可以標一個等級。
5. **順序**：開工前要確認什麼、什麼情況要停 → 不能做的事 → 怎麼驗證算做完 → 碰到才讀的文件索引。
6. **長度**：主要靠第 1 點篩；驗證器另外擋一條寬鬆的上限，防止長度慢慢漲回去。上限的數字還沒定，見[待決事項](open-questions.md)。
7. **維護**：AI 同一個錯犯兩次才加一條；過期的規則馬上刪；改了重要規則，用實驗實測過才算數。
